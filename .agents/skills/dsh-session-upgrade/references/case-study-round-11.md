# 案例：v0 → v2 会话格式升级（第十一轮 DV-11 完整剧本）

> 来源：`docs/todo/legacy-session-update.md`（任务书原件）、
> `docs/audit/2026-09-08-dv10-dv11-closure-review.md`（审计）、
> `docs/research/clat-legacy-session-update.md`（验证记录）。
> 本文件是该剧本的技能化复述，实施时以不变量为准。

## 背景与决策链

- 初始裁定（零用户教条）：旧资产不迁移，旧会话只读；
- 负责人显式改裁（2026-09-07）：授权 `/update` 显式升级——普通
  打开仍只读，仅旧版当前会话出现并接受此命令，升级完成入口
  立即消失；
- 定位根因：发现与解码认 v0，但 arm 无条件建可写 coordinator、
  prepare 拒 v0，resume 死锁——只读能力底层已有，缺的是接线。

## 七条不变量（实施与判别测试的唯一依据）

1. 普通打开/回放/切换/退出旧会话**不改 v0 字节**：不补 end-seed、
   不修复撕裂尾、不扫附件、不写 checkpoint、不创建 writer；
2. 所有持久生产者在只读会话**拒写**；运行必须在模型调用与工具
   副作用**之前**拒绝；只读会话仍可浏览、切出、退出、显式升级；
3. `/update` 仅升级**当前 CLAT 管理的顶层 v0 会话**；新版会话
   隐藏且不可执行；未来世代拒绝且不回落；
4. **v0 原件永久保留**：锁内完整转换验证后以 no-overwrite 原子
   发布 v2；发布前失败不得留下可发现的半个 v2；
5. v0 chunk→v2 内嵌 stream、事件 seq、provenance/surface 引用
   必须一致映射；无法无损处理的输入**明确拒绝**，不静默删消息、
   不制造"兼容"数据；
6. 发布 v2 是持久化提交点；重挂失败不得声称未升级或回滚已发布
   文件；重试能从已存在 v2 恢复；
7. 路径围栏、锁冲突、故障恢复、重复执行、附件原引用、回放等价、
   升级后写入/退出/重开——全部要有判别测试。

## 施工顺序（红证先行）

1. **红证**：v0 经正常 resume 失败的测试；梳理 coordinator、
   journal、checkpoint、附件清扫与命令/运行入口的全部写入点；
2. **无 writer 的只读 coordinator**：沿既有 resume/view 流程恢复
   展示，集中拒写（不是散落 if）；
3. **独立纯转换器** + v2 验证；持久层锁内读取/原子发布；
   服务层重挂；
4. **注册 `/update`**（目录动态门控：只在旧版当前会话可见）；
   同批更新 storage/usage 文档与映射决策记录；
5. 验证矩阵：pre-fix 红、语义变异、**真实 v0 副本**演练（绝不改
   用户原数据）、全量 gates、（平台语义改动时）ci-box。

## 发布序列（一次性原子动作，顺序不可换）

```
租约（session.lock 跨进程互斥）
  → 读 v0 + 拒绝撕裂尾截断场景的含糊处理
  → 纯转换器 convert()
  → 转换产物字节往返验证（重读重解码 == 转换器输出）
  → 源文件 revision 复验（防 TOCTOU：源没被并发改）
  → 临时文件 + no-overwrite 硬链接发布（link 已存在即失败）
  → 目录 fsync
  → 重武装（stage_resume + arm_session 从 v2 全新构建）
```

任何一步失败：清理临时物，v0 原样，用户可重试。

## 审计验证实录（可复用的判别手段）

- 变异"发布后删 v0"→ 三条测试腿红（原件保留被钉住）；
- 变异 HMAC 换零 → cookie recipe 腿红（证明测试有牙）；
- 目录门控核实：非旧版会话看不到命令、执行被拒三处拒写点；
- 6 份真实旧日志只读转换演练全过、原件字节未动；
- 该件获评系列"质量最高件"的原因：七不变量一条不缺 + 故障
  注入齐备（每个发布步骤都有失败路径测试）。
