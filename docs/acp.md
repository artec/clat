# ACP external Agents

CLAT runs locally configured Agent Client Protocol (ACP) v1 Agents over stdio. In **Settings → External Agents → Add Agent**, choose **Install steps** on a preset to open the official installation page. Complete the installation on the computer running the shared Host and return to **Check again**. Terminal commands and other manual steps are under **Manual installation**. When the launchers are found, check the Agents you want and choose **Add selected**. The Host saves the valid configurations together and leaves any failed entries selected for retry. Each Agent handles startup and sign-in when used.

Presets cover Codex, Claude Code, OpenCode, DeepSeek Harness, Grok Build, GitHub Copilot CLI, Qoder CLI, Antigravity CLI, Gemini CLI and Kimi Code. Antigravity CLI requires 1.5.0 or later. Qoder CLI includes ACP and uses the sign-in from `qoder login` on the Host. The Codex and Claude Code presets use separate ACP adapters. **ACP adapter not found** means CLAT found the ordinary CLI but could not locate its ACP launcher.

- **Codex:** With npm on the Host, run `npm install -g @agentclientprotocol/codex-acp` to add `codex-acp`. [Codex adapter setup](https://github.com/agentclientprotocol/codex-acp#installation)
- **Claude Code:** With npm on the Host, run `npm install -g @agentclientprotocol/claude-agent-acp` to add `claude-agent-acp`. The maintainer also ships standalone executables. [Claude adapter setup](https://github.com/agentclientprotocol/claude-agent-acp#standalone-executables)

The Windows guides use directly executable launchers. Qoder supplies a native installer for Windows x64. The guides for Codex, DeepSeek Harness and Gemini CLI use WSL, where the CLAT Host must also run.

On macOS and Linux, CLAT checks script launchers that declare an absolute interpreter path or use a simple `/usr/bin/env` shebang. For a named interpreter, CLAT checks the shared Host's PATH, active environments and common installation locations, including Node.js and Python versions managed by nvm, fnm, pyenv, uv, mise and asdf. A single detected version or one unambiguous configured default can be used without changing the Host's PATH. If CLAT finds multiple versions and cannot select one, it reports that separately. When a runtime cannot be located, **Installation help if needed** is available under **Runtime help**. ACP support and sign-in are checked when the Agent connects.

For a custom installation, choose **Advanced configuration** or use **Edit** on an existing row to enter an absolute executable path, an argument array and optional Host environment variable **names**. CLAT starts the configured executable directly, without relying on shell aliases. On Windows, choose a directly executable launcher rather than a batch file. Trust the executable for each project before starting it. You can select an Agent and confirm **Trust for this project** directly in the delegation or new external session dialog, then choose **Start** when ready. An executable or launch configuration change requires renewed trust.

- In the composer, choose **+ → Skills and extensions → External assistance**. Review the task and project directory before sending. The delegation card shows progress and offers cancellation. A newly finished task appears briefly above the composer. To revisit finished tasks, open **External assistance → Delegation history** in the same conversation. **Open details** shows the task, reply and expandable execution log. When the Agent completes with a final answer, CLAT queues that answer and the confirmed task for the original conversation. The continuation follows that conversation's existing permissions and can be cancelled before admission. The chat displays the continuation labels in the current interface language.
- In the project sidebar, choose **New external session** to open a dedicated Agent conversation. Use the **Agent commands** picker for commands advertised by the Agent. **Settings → External Agents → External sessions** opens previous local transcripts. **Browse Agent history** lists sessions if the Agent advertises that capability. CLAT imports sessions from the listing for the current project. Closing a connection preserves local history. Deleting from the Agent requires a separate confirmation.
- In the standalone or Host-connected TUI, start with `/acp`. Use `/acp add JSON`, `/acp agents` and `/acp trust ID REVISION` to configure a project. Sensitive subcommands (`trust`, `revoke`, `remove`, `delete`) first prefill the command with `--confirm` and ask you to confirm it. Use `/acp delegate AGENT TASK`, `/acp new AGENT`, `/acp send SESSION TASK`, `/acp status ID` and `/acp cancel ID` for work. The detail panel refreshes while work is in progress. `/acp remote AGENT [CURSOR]` lists Agent history. Use `/acp import AGENT REMOTE_ID` with an ID from the current project's listing.

The external executable has the Host account's OS permissions. It may use its own credentials, tools and network. CLAT-mediated file operations are held to a project boundary and writes require approval. Plan Mode and Read Only disallow starting an external Agent from that CLAT session. See [Permissions](permissions.md) and the [ACP trust model](https://agentclientprotocol.com/protocol/v1/security-considerations).

## Capability coverage

| Surface | Current implementation |
| --- | --- |
| Transport | ACP v1 JSON-RPC over managed local stdio. |
| Session lifecycle | New, prompt, cancel, negotiated load/resume/list/close/delete. History remains locally viewable when the Agent cannot restore its context. |
| Authentication | Agent-handled authentication and negotiated logout. Terminal authentication is pending. |
| Content | Text in the composer and TUI. Web/PWA/Desktop dedicated external sessions can send supported raster image and audio attachments with a capable Agent. Host prompt actions also accept resource links and capability-gated embedded resources. User-supplied session instructions and additional canonical project subdirectories are available through Host session options. |
| Agent updates | Streaming messages, thought and tool updates, plans, commands, session metadata, notices, usage and compaction notifications are collected. Web/PWA/Desktop can show body text, image and audio blocks, resource references, plans and context usage. TUI shows text and references. |
| Client callbacks | Permission questions, bounded form interaction and project-fenced text reads/writes. The gated terminal callbacks are available on macOS through a project-read/temp-write and network-denied profile. URL-mode elicitation and hosted terminals on Windows/Linux are pending. |
| MCP sharing | Empty by default. Explicit session options can share credential-free HTTPS endpoints if the Agent advertises the chosen MCP transport. Managed credential-bearing and stdio server forwarding are pending. |
| History | External transcripts and pending continuations are stored in the Host's ACP catalog. The CLAT continuation writes through normal journal admission with an idempotent external-task source. |
| Deployment | User-installed local Agents. Registry installation, remote ACP, v2 draft and the ACP server role are outside this integration. |

ACP wire behaviors are documented in the [official v1 protocol](https://agentclientprotocol.com/protocol/v1/overview). See [Gemini CLI ACP mode](https://geminicli.com/docs/cli/acp-mode/) and the [Codex ACP adapter](https://github.com/agentclientprotocol/codex-acp) for external launch configurations.
