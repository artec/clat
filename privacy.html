Privacy Policy

Last updated: November 2026 · Applies to the CLAT CLI, desktop client, web workbench, and Microsoft Store edition

The short version. CLAT is local-first: conversations, projects, credentials, and settings live on your device. There are no accounts, no telemetry, no ads, and no CLAT cloud that could collect your data. Traffic leaves your machine only when you configure a model provider or explicitly use a feature that needs the network — and the code is open source, so every claim here can be audited.

What stays on your device

Everything CLAT remembers about you is a local file under ~/.clat. Nothing here is synced or uploaded.

  • Session journals — append-only, DSH-compatible conversation logs, with attachments and rebuildable history-search caches
  • Credentials — per-vendor model API keys in ~/.clat/credentials.json (0600), and quota-console authorizations encrypted at rest
  • Project knowledge — memory, goals, trust decisions, and granted plugin write permissions
  • Extensions — installed plugin packages with their signatures and rollback records

Quit CLAT and delete ~/.clat to erase all of it at once. Uninstalling leaves that directory untouched; whether to remove it is your call.

What CLAT never does

  • No accounts, sign-ups, or CLAT-operated user profiles
  • No telemetry, analytics, or crash-report uploads built into the app
  • No advertising and no tracking SDKs
  • No sale or sharing of data — conversations never pass through a server we operate

What leaves your device — only when you use it

Every feature below is off until you configure or invoke it. As with any HTTPS traffic, the receiving service sees the request's origin IP.

Model providers

When you send a prompt, the instruction itself, the project file content the agent reads, attached images, tool results, and the conversation context needed are transmitted to the model service you selected — a direct vendor (DeepSeek, GLM, Qwen, Kimi, Tencent) or a gateway channel such as OpenCode Go that serves many vendors' models. Your API key is sent only to that service, for authentication. The service processes the content under its own privacy policy.

Plugin market

Browsing, searching, or installing from the plugin market (pi.at.cn) sends your search terms and package requests to the market service, which this project operates; we keep only the technical logs needed to serve it. Packages are signature-verified on your device before activation.

Update checks

clat upgrade --check and the desktop updater request a signed version manifest (latest.json) from GitHub Releases.

Web search and fetch

The built-in web_search / web_fetch tools send your query or target URL to the search backend you configured: DeepSeek's search API when a key is set, or a shared keyless fallback service operated by this project. Direct HTTP fetches are performed from your machine.

Console quota authorizations

The quota indicators can connect to your provider consoles to show your own usage and balance. Each authorization is opt-in, its credential is stored locally, and it is used only to read usage numbers:

  • Qianwen AI Platform — sign in through the platform's device flow: you approve in the browser, and the resulting credential is stored locally, encrypted at rest with an embedded key; the model API key is never involved
  • Aliyun Bailian — the browser calls back to a local listener on this machine and hands CLAT the console access token; the listener exists only during sign-in (cancelling closes it at once), and a callback arriving afterwards is never stored
  • Tencent Hunyuan — you save a Tencent Cloud API key, used only for TC3-signed quota reads against the Tencent Cloud endpoint

Authorizations are shared across projects on the same Host and can be reviewed or removed any time in Settings → Authorizations; removing one deletes the stored credential.

WeChat remote

Only if you start clat serve --im wechat: the messages, images, and approvals you exchange through WeChat traverse Tencent's messaging infrastructure, under Tencent's privacy policy.

External agents and extensions

Tasks you delegate to an ACP external agent run against software you installed and trust on this machine; the task content and results follow that agent's own policies, including its model provider. The same applies to MCP servers and plugins you install: they are third-party software you chose to run, and their own network behavior and privacy policies apply.

System permissions CLAT may request

  • File access is limited to the projects you open and the directories you explicitly grant
  • Application control (macOS Accessibility, Windows UI Automation) reads interface trees locally; sensitive controls ask every time, and decisions are reviewable via /ui-consents
  • Outside Full Access, commands run under OS sandbox confinement (macOS Seatbelt, Windows restricted token)
  • The local workbench clat serve binds to 127.0.0.1 by default; remote access requires credentials, sessions use HttpOnly cookies, and credentials never appear in URLs

Third-party services

Model content is processed by the service you choose — a direct vendor such as DeepSeek, GLM (Zhipu), Qwen (Alibaba), Kimi (Moonshot), or Tencent Hunyuan, or a gateway channel such as OpenCode Go (opencode.ai), which serves many vendors' models and carries its own workspace data-residency setting — under that service's privacy policy. Release downloads and update manifests come from GitHub; WeChat messages traverse Tencent's infrastructure. The plugin market (pi.at.cn) and the shared keyless search fallback are operated by this project and keep only the technical logs needed to serve them.

About this policy

  • Scope — the CLAT command-line tool, desktop client, web workbench, and Microsoft Store edition
  • Children — CLAT is a developer tool and is not directed to children
  • Changes — this page may change as CLAT evolves; the date above always reflects the current version
